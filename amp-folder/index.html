    The AMP folder¶

    Everything the app writes lives in AMP/. Both ./gradlew :desktopApp:run and the packaged app (DMG, MSI, DEB) keep it in the user's application-data folder: ~/Library/Application Support/amie pilot/AMP on macOS, %APPDATA%\amie pilot\AMP on Windows, ~/.local/share/amie-pilot/AMP on Linux (under $XDG_DATA_HOME when that is set). The Gradle run task hands the app its resources folder, just as the packaged app has one, and that is what picks this folder. On its first start the folder is seeded from the AMP/ shipped inside the app (backend.json, keycloak.json, componentSettings.json, pluginDir/, env/, sample-intents.csv), which is made from amieApplication/desktopApp/AMP/ in the repository; the dummy model is written next. Started some other way, such as running MainKt straight from the IDE, the app keeps AMP/ in its working directory instead. AMIE_AMP_DIR names another folder in every case; the tests use it to work in amieApplication/desktopApp/build/test-amp. The amie.amp.dir system property does the same when AMIE_AMP_DIR isn't set: an exported bundle's runner uses it for the AMP/ beside it, and amie.models.dir for its models/bert/. Every model lives under models/, one folder per kind (below). Nothing is kept anywhere else on the machine, so copying this folder moves your scripts, models, metrics, plugins and sign-in to another checkout or machine.

    The models folder¶

    Folder Holds Was, before November 2026
    models/bert/, models/bert/bge/ The NER model and the bge encoder every intent model is trained on; ./AMP/setup/setup.sh puts them there the same
    models/intents/<name>/ The trained intent models (the table above), with models/intents/modules.json as their registry modules/
    models/text/<name>/ The text models, Llama and Qwen: ONNX Runtime GenAI exports textModels/
    models/speech/<name>/ Whisper and the voices speech.jar runs pluginDir/config/speech/models/
    models/imported/<name>/ Models brought in from outside, such as a Hugging Face repo: the downloaded files under their repo paths (onnx/model.onnx stays as it is) and a source.json; initMod("<name>") opens one new

    The app moves an older folder into place when it starts (ModelsMigration, before anything reads a model): an old folder whose new one isn't there yet is renamed, on the same volume, so nothing is copied; a symbolic link moves as a link. When both are there nothing moves: the app reads the new one and the console says which folder to tidy. Nothing is deleted or overwritten, and every move is logged. A folder that can't be written is read as it is. speech.jar reads its models where models= in pluginDir/config/speech/speech.properties says, so the move sets that to models/speech when the setting is empty or names a folder that is gone; a setting that names a folder that is there is left alone. ModelFolders is the one owner of these paths in the code; until the next release it still reads an old folder whose new one isn't there.

    An imported model's source.json says where it came from and which format to open it in:

    {"source": "huggingface", "repo": "owner/name", "revision": "<commit sha>", "format": "onnx", "files": [{"path": "onnx/model.onnx", "size": 90387630}], "downloadedAt": "2026-11-06T10:00:00Z", "task": "text-classification", "labels": ["greeting", "lights", "weather"]}

    format is onnx, torchscript, tensorflow or tflite; task is the Hub's pipeline tag (null when it has none) and labels what the model's config.json names (id2label, in order), both read by the Models page without opening the model; a source.json from before has neither, which reads as none. A download in progress lives in models/imported/.incoming/<name>/, each file as <path>.part until its size checks. The folder moves into place only when it is whole, so a folder under models/imported is always complete. A download cancelled from the Models page removes its .incoming folder; one cut short in any other way leaves it, for the next download to go on from.

    Configuration files¶

    keycloak.json is written with defaults on first start:

    {
  "baseUrl": "http://localhost:8080",
  "realm": "master",
  "clientId": "amie",
  "clientSecret": "<the amie client's secret>",
  "redirectPort": 48080
}

    Environment variables KEYCLOAK_URL, KEYCLOAK_REALM, KEYCLOAK_CLIENT_ID, KEYCLOAK_CLIENT_SECRET override it.

    backend.json names the Amie backend, the website and the S3 service that keeps package jars; AMIE_BACKEND_URL, AMIE_SITE_URL and AMIE_S3_URL override it. With Keycloak on port 8080, run the backend on another port (AMIE_BACKEND_PORT=8090) and set baseUrl here.

    Metrics format¶

    metrics.json is a list of runs; the last one is the current model:

    {
  "runs": [
    {
      "createdAt": "2026-10-14T14:02:11Z",
      "samples": 240, "trainSize": 192, "validationSize": 48,
      "accuracy": 0.917, "macroF1": 0.905,
      "labels": { "lights": { "precision": 0.933, "recall": 0.933, "f1": 0.933, "support": 15 } },
      "confusion": [[14, 1], [1, 14]],
      "warnings": [],
      "validation": "split 20%"
    }
  ]
}

    confusion[truth][prediction] is indexed like the label list in module.json.

    Times in these files (createdAt here, in module.json and in groups.json, a package report's ranAt, a jar's fetchedAt) are instants in UTC, as the trailing Z says; the Models page and the console show them in this machine's local time. A time written into text that is kept, such as a rollback's note ("v1 brought back (made 2026-10-21 04:03 +02:00), replacing v2"), carries its offset from UTC, so it reads right on any machine.

    Runs written since versions are kept carry more, all optional (older runs have none of it and read the same): kind (build, fine-tune, calibration, validation, rollback) and version; analysis with ece, the reliability bins, the selective gates, the mistakes and suspects (texts only when the model keeps texts), the temperature, eceBefore and a fine-tune's learning curve; baseline, the head before a fine-tune or a calibration scored on the same rows; accuracyRange and macroF1Range (low, high: where the score fell in the middle 95% of 1,000 resamples of the run's rows, see how far the scores hold); leakage (checked, exact, near, the warning it gave, and for a model that keeps texts up to ten pairs of a scored row and the row it learned from, see rows it learned from); and a note. Each entry of candidates adds the cross-validation scores (cvAccuracy, cvMacroF1, cvSpread, folds), where early stopping stopped and which epoch it kept (stoppedAt, keptEpoch), and its learning curve (up to 41 points of loss and accuracy on the training and validation rows).
